# fx_autotrader

機械学習でFXの値動きを予測し、自動売買する Python ボットです。
接続先は **GMOコイン「外国為替FX」**（既定）と **OANDA** に対応しています。

## しくみ

```
ブローカーAPI ──▶ 過去データ(CSV) ──▶ 特徴量 ──▶ 勾配ブースティングで「N本先が上がるか」を予測
                                                   │
                     ┌─────────────────────────────┴───────────────┐
                     ▼                                             ▼
          ウォークフォワード・バックテスト                    ライブ売買（確定足ごと）
          （再学習しながら未学習期間だけ評価）              上昇確率 > 閾値 → 買い
                                                            上昇確率 < 1-閾値 → 売り
                                                            それ以外 → ノーポジ
```

| ファイル | 役割 |
| --- | --- |
| `fxbot/gmo.py` | GMOコイン 外国為替FX API クライアント（足の取得・資産・建玉・注文） |
| `fxbot/oanda.py` | OANDA v20 API クライアント |
| `fxbot/features.py` | 特徴量（リターン、移動平均乖離、RSI、ボラティリティ、ATR、時刻）とラベル |
| `fxbot/model.py` | モデルの学習・予測・保存、確率→ポジション変換 |
| `fxbot/backtest.py` | ウォークフォワード検証とコスト込みの成績評価 |
| `fxbot/live.py` | 自動売買ループ（損切り注文付き、最大損失で全決済して停止） |
| `fxbot/cli.py` | コマンドライン入口（`--broker gmo` / `--broker oanda`） |

## セットアップ（GMOコイン）

1. GMOコインで口座開設し、**外国為替FX口座**も開設する
2. 依存パッケージをインストール

```bash
python -m venv .venv && source .venv/bin/activate
```

```bash
pip install -r requirements.txt
```

データ取得・バックテスト・学習には API キーは不要です。API キーは自動売買（`live`）を始める直前に作ります（後述）。

## 使い方

### 1. 過去データを取得

```bash
python -m fxbot.cli fetch --instrument USD_JPY --granularity H1 --start 2023-10-28 --out data/USD_JPY_H1.csv
```

GMOコインの足データは2023年10月27日以降のみ提供されています。1時間足は1日ごとに BID と ASK を取得するため10分ほどかかります。
OHLC は BID と ASK の平均（仲値）、`spread` 列は各足の終値時点のスプレッド（ASK−BID）です。

### 1-2. 学習用の長期データを取得してつなぐ

GMOコインのデータは約3年分しかないため、Dukascopy（スイスの銀行）が公開している過去データ（2010年〜）を
**学習用に**追加します。評価（バックテスト・設定選び）は GMOコインのデータの期間だけで、GMOコインの実スプレッドを使って行います。

```bash
python -m fxbot.cli fetch-history --start 2010-01-01 --end 2023-11-01
```

```bash
python -m fxbot.cli combine
```

`data/USD_JPY_H1_combined.csv` に、Dukascopy の長期データの後ろに GMOコインのデータをつないだものができます。
以降のコマンドはこのファイルを使い、`--eval-start`（既定 2023-11-01）以降を評価、それより前は学習にだけ使います。

### 2. 設定を選ぶ（tune）

```bash
python -m fxbot.cli tune
```

予測期間を前半の**検証期間**と後半の**最終確認期間**（既定40%）に分け、次の組み合わせを検証期間だけで比較して
シャープレシオが最も良い設定を選びます。選んだ設定を最終確認期間で一度だけ評価するので、
「過去にだけ当てはまる設定」を選んでしまっていないかを確かめられます。

| 項目 | 意味 | 既定の候補 |
| --- | --- | --- |
| `--horizons` | 何本先の上下を予測するか | 1, 2, 4 |
| `--train-windows` | 直近何本で学習するか（全本数以上なら全データ） | 4000, 25000, 1000000 |
| `--thresholds` | エントリーする上昇確率の閾値 | 0.52, 0.55, 0.58, 0.6 |
| `--max-spread-ratios` | スプレッドが直近のふだんの値（中央値）の何倍を超えたら売買しないか（1000は実質制限なし） | 1.0, 1.5, 3.0, 1000 |

**最終確認期間の成績がプラスで、検証期間と大きくかけ離れていないこと**が、次に進む目安です。

### 3. バックテスト（選んだ設定の詳細確認）

```bash
python -m fxbot.cli backtest --horizon 2 --train-window 1000000 --threshold 0.58 --max-spread-ratio 1.5
```

出力の見方:

- `total_return` / `buy_and_hold`: 戦略と単純保有の累積リターン
- `sharpe`: 年率シャープレシオ（1以上が一つの目安）
- `max_drawdown`: 最大下落率
- `trades` / `exposure`: 売買回数とポジション保有率

売買コストは、各足の実際のスプレッドの半分＋手数料（`--fee`、既定はGMOコインAPIの1通貨0.002円）を片道ごとに差し引きます。
スプレッドが直近120本の中央値の `--max-spread-ratio` 倍を超える足ではポジションを変えずに持ち越します（自動売買でも同じ規則で見送ります）。
固定の値にしないのは、ブローカーがスプレッドを改定しても追従できるようにするためです（GMOコインのUSD/JPYは2025年秋に0.2銭→0.5銭に変わっています）。

GMOコインのUSD/JPYでは、日本時間の朝5〜8時台にスプレッドが通常の数十倍（10銭以上）に広がります。

### 4. 学習してモデルを保存

```bash
python -m fxbot.cli train --horizon 2 --train-window 1000000 --model models/model.joblib
```

### 5. 自動売買

自動売買の前に、次の準備をします。

1. 暗号資産口座へ日本円を入金し、会員ページ・アプリの【振替】で**外国為替FX口座へ振替**する
2. 会員ページの「API」から外国為替FXの API キーを作成する
   - 権限は「口座情報の取得」と「注文」を有効にする
   - 初めて API キーを作成してから30日間は API 経由の取引手数料が無料なので、使い始める直前に作るのがおすすめ
3. 認証情報を環境変数に設定（`.env.example` を参照）

```bash
export GMO_API_KEY=xxxx GMO_API_SECRET=xxxx
```

GMOコインの API で使えるデモ環境が無い場合は、まず**最小に近い数量で本番口座**を使って動作確認します
（API の最小注文数量は主要通貨ペアで100通貨。最新の条件は公式サイトで確認してください）。

```bash
python -m fxbot.cli live --model models/model.joblib --units 100 --threshold 0.58 --max-spread-ratio 1.5 --stop-loss 0.5 --max-loss 0.05
```

- 確定足が更新されるたびに予測し、目標ポジション（+units / 0 / -units）に建て直します
- その時点のスプレッドがふだんの `--max-spread-ratio` 倍を超えていれば建て直しを見送り、次の足で判断し直します
- 新規建て直後に、`--stop-loss`（価格単位、USD/JPYで0.5なら50銭）離れた位置へ決済の逆指値を置きます
- 決済時は、置いてある逆指値を取り消してから成行で決済します
- 起動時の資産から `--max-loss`（既定5%）以上減ると全決済して停止します
- API エラーなどは握りつぶさずに停止します。常時稼働させる場合は systemd などで再起動を管理してください

### GMOコイン接続で実地確認が必要な点

API 仕様は公開 SDK のソースと公式サンプルから実装しており、実口座ではまだ検証していません。
最初は少額で、次の点を確認してください。

- 決済の逆指値が無い状態で決済したとき、一括取消（`cancelBulkOrder`）がエラーにならないか
- 逆指値の価格が想定どおり（約定価格から `--stop-loss` 離れた位置）に置かれているか

## OANDA を使う場合

`--broker oanda` を付け、`OANDA_API_TOKEN` / `OANDA_ACCOUNT_ID` / `OANDA_ENV` を設定します。
デモ口座（`OANDA_ENV=practice`）で動かせます。

## テスト

```bash
pytest
```

合成データとモックで、特徴量が未来を参照しないこと、バックテストのコスト計算、API の署名と注文内容、
売買ループの挙動を確認しています。

## 注意

- FX の値動き予測は非常に難しく、バックテストで勝てても将来の利益は保証されません
- 実際のお金で動かすときは、損失が出ても問題ない金額で、自己責任で運用してください
- 改善の余地: 特徴量の追加、閾値・ホライズンの調整、ATR 連動の損切り幅、資金に応じたロット計算、通知機能 など
