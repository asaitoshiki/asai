# CLAUDE.md

冷蔵庫キーパー（食品ロスを減らす Android アプリ）の開発方針。
詳細な仕様は `docs/fridge-app-spec.md` を参照すること。

## このアプリのアイデンティティ

「在庫を管理する」アプリではなく「**食材を腐らせない・捨てない**」アプリ。
機能を足すかどうかは常に「**入力の手間が増えないか**」で判断する。
入力が面倒 → 在庫と現実がズレる → 使われなくなる、が最大の離脱要因である。

## 技術構成

Kotlin / Jetpack Compose / Room / DataStore / WorkManager / CameraX / ML Kit（オンデバイス）/ Glance / Hilt / Coroutines・Flow。

MVVM + Repository の薄い構成。

```
ui/      Compose 画面 + ViewModel（UiState を StateFlow で公開する）
domain/  期限計算・ストリーク判定などのビジネスロジック
data/    Room の Entity/DAO、Repository、DataStore
```

## 絶対の制約

- **完全ローカル完結**。サーバー通信・外部 API を一切行わない
- **AI / LLM を使わない**
- ユーザーデータを端末外へ送信しない

## 安全に関する決まり（食品を扱うため最優先）

- 推定期限を表示する箇所には必ず「**目安**」バッジを付ける
- 消費期限（`USE_BY`）は賞味期限より**強い警告表示**にする。過ぎたら食べてはいけないため
- 「まだ食べられます」など**安全を断定する文言を表示しない**
- 期限内であることを緑などで「安全」と印象づけない
- 通知は不達前提で設計する。**アプリを開けば必ず全体の状態が把握できる**こと

## コーディング方針

- **コメントは日本語**。コードブロックの概要や、コードで表現できない背景を簡潔に書く
- **既存コードを読んでから書く**。編集対象だけでなく呼び出し元・依存先・類似実装も確認する
- **現状優先**。既存の構造・パターンに合わせ、必要最低限の変更で実装する
- **YAGNI**。「将来使うかも」で作らない
- **最小依存**。クラス間の依存を最小限に保つ
- **攻撃的プログラミング**。存在すべき値は直接アクセスする。防御的な存在チェックや null 許容は書かない。フレームワークが保証する値の検証も書かない
- **条件分岐を避ける**。フラグ制御は最終手段。早期リターン／ガード節で浅く保つ

### 攻撃的プログラミングの正当な例外

以下の null は「防御」ではなく**正しいドメインモデリング**であり、non-null 化してはならない。

| 対象 | null が意味するもの |
|---|---|
| `FoodItemEntity.expiryDate` | 期限が印字されていない食品（野菜・肉・魚など）。登録時に入力を必須にしてはならない |
| `PresetExpiryTable.daysFor()` | その カテゴリ × 保管場所 に目安を出せない。期限なし扱いとする |
| `JanProductDictionaryEntity.defaultCategory` | 商品名だけ覚えていてカテゴリが未特定 |

## データの決まり

- `LocalDate` は ISO-8601 文字列（`yyyy-MM-dd`）で保存する。辞書順と日付順が一致し、SQL 側で `MIN`/`MAX`・範囲比較がそのまま使えるため
- Enum は `name()` で保存する。序数だと定数の並び替えで既存データが壊れるため
- **推定期限は DB に保存しない**。参照時に domain 層で導出する
- 期限順の並べ替えは SQL ではなく domain 層で行う。推定期限が SQL からは見えないため

## 開発の進め方

フェーズごとに区切り、各フェーズ完了時点で動作確認できる状態にする。一度に全部書かない。

| フェーズ | 内容 | 状態 |
|---|---|---|
| Phase 1 | 基盤（Room、Repository、Hilt、Enum、プリセット期限テーブル） | 完了 |
| Phase 2 | コア機能（手動登録／編集／削除、期限順ホーム、緊急度の色分け、推定期限の導出） | 未着手 |
| Phase 3 | 消費とストリーク | 未着手 |
| Phase 4 | 通知（WorkManager） | 未着手 |
| Phase 5 | 入力削減（バーコード、JAN 辞書、テンプレート） | 未着手 |
| Phase 6 | 仕上げ（ウィジェット、エクスポート／インポート、免責同意、設定） | 未着手 |

## v1.0 のスコープ外

勝手に実装しないこと：AI/LLM 連携、レシートOCR、外部 API 連携、アカウント・クラウド同期・共有、
レシピ提案、栄養成分・アレルギー情報（安全上あえて扱わない）、広告・課金、冷蔵庫イラスト UI。
